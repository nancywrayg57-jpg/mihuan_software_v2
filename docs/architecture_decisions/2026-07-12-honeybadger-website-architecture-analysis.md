## 架构基线

- 页面范围：首页、产品介绍、新闻资讯、人才招聘、关于我们。
- 公共层优先：页头导航、页脚、面包屑、导航栏语言切换、全局客服悬浮按钮。
- 多语言内容按“页面 -> 模块 -> 字段 -> locale”组织，中文、英文、俄语必须是真实内容切换。
- 公共配置集中管理：域名、企业邮箱、客服渠道、ICP、版权、品牌关系说明、联系方式。
- SEO 与上线能力首期考虑：title、description、canonical、hreflang、`sitemap.xml`、`robots.txt`、正式域名、HTTPS、Let's Encrypt 自动续签。

## API 与数据约束

- 首期可无运行时后端；若引入 CMS、联系表单或内容 API，必须以 `openapi.yaml` 为前后端契约单点信任来源。
- 所有 CRUD、查询、更新必须携带 `tenant_id` 或 `org_id`，禁止仅凭主键操作。
- 数据库结构变更必须通过带时间戳的增量 migration，包含 `.up.sql` 与安全 `.down.sql`，禁止直接覆盖 `schema.sql`。
- 复杂状态使用状态机，禁止硬编码 `status = 1` 类流程。
- 若未来涉及金额、库存、计费、额度，必须使用 decimal 高精度方案，禁止 Float/Double 和原生浮点算术。
- 所有 fetch/API 调用必须检查 `response.ok` 与 `content-type`，并防御 HTML 错误页、空响应、非 JSON 响应。
