# 蜜獾项目端测（E2E）事项清单

## 1. 文档依据与测试边界

### 1.1 编制依据

本清单仅依据以下三份核心文档梳理：

1. `docs/蜜獾官网项目需求分析.md`
2. `docs/开发路线图.md`
3. `docs/蜜獾官网项目架构分析.md`

### 1.2 首期 E2E 覆盖范围

| 范围 | 覆盖内容 |
|---|---|
| 站点类型 | 蜜獾正式对外发布的企业官网独立站 |
| 正式域名 | `https://www.honeybadgersoft.com/` |
| 一级页面 | 首页、产品介绍、新闻资讯、人才招聘、关于我们 |
| 产品二级页 | `跨境网络服务.html`、`en/跨境网络服务.html`、`ru/跨境网络服务.html`（归属产品介绍，不新增一级导航） |
| 语言范围 | 中文、英文、俄语 |
| 公共能力 | 页头导航、页脚、面包屑、导航栏语言切换、全局客服悬浮按钮 |
| 内容能力 | 结构化内容文件、三语页面内容、页面 SEO、公共配置、新闻与招聘内容 |
| 联系能力 | 阿里云企业邮箱、微信/QQ/钉钉客服路径、页内 CTA、页脚联系入口 |
| 发布能力 | 正式域名、HTTPS、Let's Encrypt 自动续签、`sitemap.xml`、`robots.txt`、404 页面 |
| 架构联动 | 浏览器 -> 正式域名 -> CDN/Nginx/静态资源服务 -> 预渲染或静态站点产物 -> 结构化内容文件 -> `site_config` |

### 1.3 明确不纳入首期 E2E 的范围

| 不做项 | 测试处理方式 |
|---|---|
| 会员系统 | 不编写首期登录、注册、会员中心 E2E 用例 |
| 支付、订单、库存、资金 | 不编写交易闭环、资金精度、库存扣减 E2E 用例 |
| 复杂后台 CMS | 首期不作为上线前置；仅在后续确认引入 CMS/API 后执行条件型测试 |
| 伪后台、假客服、假语言切换 | 作为验收阻断项测试，不作为可接受功能测试 |
| 无业务依据的专题页或活动页 | 不编写额外页面 E2E 用例 |

### 1.4 测试类型定义

| 类型 | 定义 | 适用阶段 |
|---|---|---|
| 普通功能测试 | 针对单页面、单组件或单交互的可用性校验 | S0-S4 |
| 全链路 E2E 测试 | 从用户访问入口出发，覆盖页面跳转、内容加载、语言切换、CTA、客服、SEO 或部署链路的闭环验证 | S1-S6 |
| 迭代测试 | 每个开发阶段完成后，对该阶段新增能力做局部验证 | S0-S5 |
| 版本验收测试 | 上线前按首期交付范围逐项确认是否满足验收标准 | S6 |
| 全量回归测试 | 修改公共组件、多语言、内容模型、部署配置或上线前，对全站核心路径重新验证 | S3-S6 |
| 条件型测试 | 仅在后续确认引入 CMS、API、数据库、表单或后台能力时执行 | 二期或需求确认后 |
