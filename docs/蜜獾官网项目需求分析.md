### 1.1 文档定位

- `docs/requirements_v2.md` 仍是当前项目的需求基线，负责定义“要做什么”。
- 本文档负责把基线需求转为可执行的开发要求、页面结构、内容模型和验收口径。
- 若本文档与 `docs/requirements_v2.md` 冲突，以 `docs/requirements_v2.md` 为准，并应先修正文档后再推进设计或开发。

### 1.2 已确认事实

- 项目为蜜獾正式对外发布的企业官网独立站。
- 官网需显著说明：蜜獾公司是俄罗斯 `zennolab` 公司在中国的运营实体。
- 正式域名为 `https://www.honeybadgersoft.com/`。
- 网站需支持中文、英文、俄语三种语言。
- 首期一级页面固定为：首页、产品介绍、新闻资讯、人才招聘、关于我们。
- 全站固定公共能力包括：统一页头导航、统一页脚、面包屑、导航栏语言切换、全局客服悬浮按钮、HTTPS 与证书自动续签。

### 1.3 当前 UI 与参考站点分析结论

基于当前 `UI/`、`docs/生产物料清单.md` 与 `docs/蜜獾官网页面文案.md`，并把 `zennolab.com` 仅作为 B2B 软件官网的信息组织和体验节奏外部参考，可得到以下可复用规律：

- 官网采用轻量 B2B 软件品牌表达，主基调为白色和浅蓝灰色背景，配合亮蓝色 CTA 与产品色点缀。
- 首页与产品页都强调“大标题 + 价值主张 + 产品截图/视觉主图 + 明确 CTA”。
- 导航结构突出产品矩阵、语言切换、支持与社区入口，说明多语言与公共入口是顶层能力，不是附属功能。
- 产品页常见模块包括：产品概览、核心能力卡片、场景说明、工作流程或价值说明、FAQ/支持、购买或咨询 CTA。
- 页面组件风格偏克制：圆角卡片、轻阴影、信息分区清晰，强调企业可信度与产品专业度。

上述规律仅作为结构和体验参考，不构成对 `zennolab.com` 的直接复刻要求。

## 2. 项目背景与目标

### 2.1 项目背景

- 蜜獾需要建设正式对外发布的企业官网，用于统一承接品牌展示、产品能力说明、企业背景表达、资讯发布与招聘信息展示。
- 官网需要在品牌表述上清晰建立蜜獾与 `zennolab` 的关系，降低用户对主体身份和服务归属的理解成本。
- 当前工作区已有 `UI/` 静态官网实现，包含一级页面、三语路径、共享样式/脚本和生产物料清单，可作为正式开发的前端页面参考与迁移基线；后续若继续静态站交付，应在此基础上完成生产化修正、旧路由清理和上线验证。

### 2.2 项目目标

- 建设一个支持正式域名访问的三语企业官网。
- 清晰展示蜜獾的品牌定位、产品能力、企业背景和招聘信息。
- 在首页和相关页面显著说明蜜獾与 `zennolab` 的关系。
- 建立可落地的信息架构、内容模型和公共组件要求，为后续设计与开发提供统一输入。

### 2.3 首期不做范围

- 不建设复杂后台 CMS。
- 不建设会员、支付、订单、库存、资金等业务系统。
- 不增加与当前需求无关的专题页、活动页或伪后台功能。
- 不以纯前端假数据或假客服入口充当正式交付。

## 3. 用户与使用场景

### 3.1 目标用户

- 潜在客户：了解蜜獾产品能力、服务方向和品牌背景。
- 潜在合作方：确认企业主体、品牌关系和联系路径。
- 求职者：查看招聘信息、理解公司定位并完成联系。
- 行业访客：浏览企业动态、行业内容与产品资料。

### 3.2 核心访问场景

- 首次访问用户快速理解“蜜獾是谁、与 `zennolab` 是什么关系、提供什么能力”。
- 潜在客户查看产品介绍页，理解产品能力、场景价值和咨询入口。
- 访客通过新闻资讯了解企业活动与行业动向。
- 求职者通过招聘页面查看岗位并联系。
- 任意语言用户可无障碍切换中文、英文、俄语内容。

## 4. 信息架构要求

### 4.1 一级导航

一级导航固定为：

1. 首页
2. 产品介绍
3. 新闻资讯
4. 人才招聘
5. 关于我们

导航栏必须同时包含语言切换入口。

### 4.2 页面层级规则

- 首页为站点根入口，不显示面包屑。
- 其余一级页面统一显示面包屑，位置位于页头导航下方。
- 若后续存在新闻详情、岗位详情、产品子模块详情等内容页，应作为对应一级页面的二级内容页管理，不新增首期一级导航项。

### 4.3 页脚结构

页脚需统一承载以下信息：

- 企业主体与品牌关系说明
- 对外邮箱
- 联系方式或联系入口
- ICP 备案信息预留位
- 版权信息预留位
- 可选的支持类外链预留位

## 5. 页面级需求

### 5.1 首页

首页应承担品牌首屏说明与站点总入口职责，建议采用与 `zennolab` 首页一致的“价值主张优先、产品矩阵承接、CTA 明确”的结构思路。

必备模块如下：

1. 首屏品牌模块
   - 显著展示蜜獾品牌主标题与一句话价值主张。
   - 显著说明蜜獾是俄罗斯 `zennolab` 公司在中国的运营实体。
   - 配置主要 CTA，如“了解产品”“联系我们”。
   - 配置品牌主视觉或产品展示素材。
2. 核心产品/能力矩阵
   - 以卡片或分区形式展示核心产品或核心服务能力。
   - 每个条目需包含名称、简述、核心价值点和跳转入口。
   - 视觉上可借鉴 `zennolab` 的产品矩阵和卡片式分区，但需形成蜜獾自身品牌表达。
3. 品牌关系与信任背书
   - 说明蜜獾与 `zennolab` 的关系、业务定位与面向市场。
   - 可展示企业资质、合作方向、服务优势或品牌背书。
4. 新闻资讯预览
   - 展示最新企业活动或行业资讯摘要。
   - 提供跳转至“新闻资讯”页面入口。
5. 招聘预览
   - 展示招聘入口、团队介绍摘要或重点岗位提示。
   - 提供跳转至“人才招聘”页面入口。
6. 全站联系入口
   - 页内需出现清晰的联系 CTA。
   - 全局客服悬浮按钮需常驻可见。

### 5.2 产品介绍

产品介绍页需参考 `zennolab` 产品页的结构规律，重点不是单纯堆文案，而是形成“产品概览 -> 核心能力 -> 场景价值 -> 素材证明 -> 联系转化”的完整链路。

#### 当前产品范围

当前对外产品范围统一为 **4 项常规产品/服务 + 跨境网络服务（含静态住宅 IP、机房 IP、动态 IP）**。产品介绍页、首页产品矩阵、导航入口、SEO、三语文案和产品详情页不得继续使用“7 项产品矩阵”或旧 ZennoLab 产品矩阵作为事实源。

| 类型 | 产品/服务 | 展示要求 |
|---|---|---|
| 常规产品/服务 | 数字化农业综合管理系统 | 作为独立产品/服务卡片和详情入口展示 |
| 常规产品/服务 | 蜜獾原图 | 作为独立产品/服务卡片和详情入口展示 |
| 常规产品/服务 | AI-FDE VibeCoding培训 | 作为独立产品/服务卡片和详情入口展示 |
| 常规产品/服务 | 社媒跨境私域陪跑 | 作为独立产品/服务卡片和详情入口展示 |
| 合并产品二级页 | 跨境网络服务 | 作为统一入口展示，内部承接静态住宅 IP、机房 IP、动态 IP 三类子服务；三类 IP 不再拆分为顶层产品方向 |

必备模块如下：

1. 页面首屏
   - 产品页主标题、副标题和一句话价值主张。
   - 代表性产品图、界面截图或说明素材。
   - 主 CTA，如“咨询合作”“获取资料”。
2. 产品/服务分类概览
   - 展示当前 4 项常规产品/服务 + 跨境网络服务合并入口。
   - 每组需至少包含名称、简述、核心用途。
3. 核心能力说明
   - 以卡片、图文模块或分段结构说明能力点。
   - 每个能力点需明确说明“解决什么问题、适用于哪些场景、对客户的价值是什么”。
4. 应用场景或行业方案
   - 对应 `zennolab` 产品页中的应用场景表达方式，展示蜜獾能力的典型使用场景。
5. 产品素材展示
   - 支持展示截图、插图、结构图、流程图或演示素材。
6. 支持与联系模块
   - 页面底部需提供咨询、邮件联系或客服入口。

跨境网络服务内部的静态住宅 IP、机房 IP、动态 IP 可在合并页内提供锚点式二级导航或子服务详情入口，不扩张为一级导航或顶层产品矩阵。

### 5.3 新闻资讯

新闻资讯页需兼顾企业内容与行业内容两类信息，参考 `zennolab` 首页的“内容入口前置”思路，但不扩张为复杂内容平台。

必备模块如下：

1. 页面首屏说明
   - 说明页面定位，例如企业动态、产品更新、行业洞察。
2. 分类切分
   - 至少支持“企业活动”和“行业新闻”两类内容展示。
3. 资讯列表
   - 每条资讯需包含标题、摘要、发布时间、封面图或缩略图。
4. 资讯详情模板
   - 若上线详情页，需有统一标题区、发布时间、正文区、相关推荐或返回入口。
5. 联系或转化入口
   - 在列表页或详情页保留咨询或联系入口。

### 5.4 人才招聘

人才招聘页需完整承载招聘信息展示，不应仅放一个邮箱或空白占位。

必备模块如下：

1. 招聘品牌说明
   - 介绍团队方向、公司定位和招聘价值主张。
2. 岗位列表
   - 每个岗位至少包含岗位名称、工作地点、岗位类型、岗位摘要。
3. 岗位详情
   - 岗位职责、任职要求、加分项、投递方式。
4. 投递与联系
   - 支持使用企业邮箱或明确的投递路径。
5. 相关补充内容
   - 可展示办公环境、团队文化或人才发展方向。

### 5.5 关于我们

关于我们页需承担企业说明和主体澄清职责，是“蜜獾与 `zennolab` 关系说明”的重点页面之一。

必备模块如下：

1. 品牌介绍
   - 品牌名称、品牌愿景、核心定位。
2. 品牌定位与形象展示
   - 品牌风格、业务方向、服务特征。
3. 企业背景介绍
   - 企业发展背景、关联关系、业务覆盖范围。
4. 公司主体说明
   - 明确说明蜜獾是俄罗斯 `zennolab` 公司在中国的运营实体。
5. 联系我们
   - 对外邮箱、客服路径、预留线下联系信息位。

## 6. 全站功能需求

### 6.1 多语言能力

- 全站必须支持中文、英文、俄语三种语言。
- 语言切换入口必须位于导航栏。
- 切换后应呈现真实完整内容，不能只切换按钮状态或页面外壳。
- 所有页面的 SEO 标题、描述、按钮文本、页脚信息、客服说明均需具备多语言版本。

### 6.2 响应式能力

- 页面必须适配桌面端与移动端。
- 导航、首屏视觉、卡片矩阵、页脚和客服浮层都需在移动端保持可用。
- 需重点校验英文和俄语文本长度对导航、按钮、卡片标题和页脚布局的影响。

### 6.3 客服与联系能力

- 全站常驻客服悬浮按钮。
- 点击后可选择微信、QQ、钉钉三种联系路径。
- 所有客服入口必须接入真实账号、二维码或跳转链接，禁止使用无效占位。
- 对外邮箱统一使用阿里云企业邮箱。
- 当前联系物料状态以 `docs/生产物料清单.md` 为准：微信/QQ/企业邮箱已确认；钉钉真实入口待配置。若微信、QQ、钉钉三通道均为上线必备，则钉钉继续作为上线阻塞项。

### 6.4 内容维护能力

- 首期默认采用结构化内容文件维护，不以复杂 CMS 作为上线前置条件。
- 新闻、招聘、产品、关于我们等页面内容应按统一内容模型组织。
- 全站公共信息需集中配置，禁止散落硬编码。

### 6.5 SEO 与发布能力

- 网站必须支持正式域名访问。
- 网站必须启用 HTTPS，并使用 `Let's Encrypt` 证书及自动续签方案。
- 页面需具备基础 SEO 能力，包括标题、描述、语言标识、规范化链接、`sitemap.xml` 与 `robots.txt`。
- 不应采用不利于搜索引擎读取的纯黑盒客户端渲染方案，除非后续实现中提供预渲染或等效能力。

## 7. 内容模型要求

首期建议采用以下结构化内容模型，以满足三语、公共配置和后续可维护性要求。

| 内容对象 | 必填字段 |
|---|---|
| `site_config` | `domain`、`brand_name`、`relation_statement`、`support_channels`、`email`、`icp_text`、`copyright_text` |
| `navigation` | `key`、`label`、`path`、`order`、`locale` |
| `page_seo` | `page_key`、`title`、`description`、`keywords`、`locale` |
| `home_sections` | `section_key`、`headline`、`subheadline`、`body`、`media`、`cta`、`locale` |
| `products` | `slug`、`name`、`summary`、`features`、`scenarios`、`assets`、`cta`、`locale` |
| `news_articles` | `slug`、`category`、`title`、`summary`、`publish_date`、`cover`、`body`、`locale` |
| `job_postings` | `job_id`、`title`、`location`、`job_type`、`summary`、`responsibilities`、`requirements`、`apply_method`、`locale` |
| `about_sections` | `section_key`、`title`、`content`、`media`、`locale` |

内容模型需遵循以下规则：

- 统一按“页面 -> 模块 -> 字段 -> locale”组织。
- 公共信息如域名、邮箱、客服渠道、品牌关系说明、备案位和版权位必须集中配置。
- 日期字段需支持统一格式化输出，不能直接以原始对象或非标准格式进入页面渲染。

## 8. 视觉与交互要求

### 8.1 视觉方向

结合当前 `UI/assets/styles.css`、`docs/生产物料清单.md` 与 `docs/蜜獾官网页面文案.md`，首期官网视觉建议遵循以下方向：

- 主视觉基调以白色、浅蓝灰色为主，建立专业、克制、可信的企业软件品牌形象。
- CTA 使用高识别度蓝色体系，局部可根据产品线引入辅助强调色。
- 模块结构强调留白、卡片、分区和清晰层级，避免信息堆叠。
- 首页与产品页应使用具有说服力的主视觉、截图或示意素材。

### 8.2 交互表达

- 导航、产品卡片、联系按钮应具备明确 hover/active 状态。
- CTA 文案应清晰区分“了解更多”“联系我们”“获取资料”“投递简历”等转化目标。
- 移动端应优先保证导航、语言切换、客服按钮和关键 CTA 的点击可达性。

### 8.3 设计边界

- 视觉风格可参考 `zennolab.com` 的节奏、层次与专业感，但不得直接复制原站内容和品牌素材。
- LOGO 可在现有基础上重设计，但最终边界需以后续确认结果为准。

## 9. 技术与实施约束

- 当前 `UI/` 静态官网实现不反向锁定最终前端框架；若后续新开工程仓或迁移到 Astro/Next/Nuxt 等方案，应以现有页面、样式、文案和生产物料为迁移基线。
- 无论后续选型为何，必须满足三语、SEO、响应式、正式域名部署和结构化内容维护要求。
- 全站公共能力应优先于单页开发，开发顺序应先完成页头、页脚、语言切换、面包屑、客服浮层，再铺设 5 个页面内容。
- 禁止以假链接、假客服、假语言切换或空数据页面充当正式完成。

## 10. 交付物要求

首期交付物应包括：

1. 官网需求文档
2. 页面信息架构
3. 视觉设计稿
4. 前端项目代码
5. 部署配置
6. 三语内容清单
7. 上线检查清单

## 11. 验收标准
