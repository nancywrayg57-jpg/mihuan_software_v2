## 1. 项目治理与边界

### 1.1 单点需求基线

1. `docs/requirements_v2.md` 是首期范围基线，负责定义“要做什么”。
2. `docs/蜜獾官网项目需求分析.md` 是开发级细化文件，负责页面结构、内容模型、交互和验收口径。
3. `UI/`、`docs/生产物料清单.md` 与 `docs/蜜獾官网页面文案.md` 是当前视觉、页面布局、内容和上线状态参考。
4. 如需求、设计和实现出现冲突，先回到 `docs/requirements_v2.md` 与需求分析文档校准，再进入开发。

### 1.2 交付边界

首期交付必须覆盖：

| 类别 | 交付内容 |
|---|---|
| 页面 | 首页、产品介绍、新闻资讯、人才招聘、关于我们 |
| 公共组件 | Header、Footer、Breadcrumb、Language Switcher、Floating Customer Service |
| 内容 | 三语页面内容、SEO 内容、客服与联系信息、备案与版权预留 |
| 工程 | 前端项目代码、结构化内容模型、构建脚本、部署配置 |
| 上线 | 域名解析、HTTPS、证书自动续签、`sitemap.xml`、`robots.txt`、上线检查清单 |

首期明确不做：

- 不建设会员、支付、订单、库存、资金等业务系统。
- 不建设复杂后台 CMS。
- 不增加无业务依据的专题页或活动页。
- 不用假链接、假客服、假语言切换、空新闻、空岗位冒充正式交付。

### 1.3 工程红线

1. 多语言切换必须加载真实三语内容，不能只切换按钮状态。
2. 客服入口必须按 `docs/生产物料清单.md` 接入真实联系渠道：微信/QQ/企业邮箱已确认，钉钉未配置前不得展示假入口，并作为上线阻塞项。
3. 公共信息必须集中配置，禁止在多个页面散落硬编码。
4. 日期必须经过统一格式化后进入模板渲染。
5. 网站不得直接复制 `zennolab.com` 的原站内容、品牌素材或受版权保护的视觉资产。
6. 若引入接口请求，所有 `fetch` 必须检查 `response.ok` 与 `content-type`，并输出明确 HTTP 错误。
7. 若后续引入 Tailwind，禁止动态拼接类名，动态布局使用 style、CSS 变量或明确枚举类名。

## 3. 技术路线建议

### 3.1 技术选型原则

当前工作区已有 `UI/` 静态官网实现，可作为正式开发的前端页面参考与迁移基线。若后续新开工程仓或迁移到组件化/SSG/SSR 方案，应先完成技术选型；若继续静态站交付，应在现有 `UI/` 基础上完成生产化修正、旧路由清理和上线验证。无论采用哪种落地方式，都必须满足以下硬性条件：

1. 支持三语路由和三语 SEO 元信息。
2. 支持预渲染、SSG、SSR 或等效 SEO 方案，避免纯黑盒客户端渲染。
3. 支持结构化内容文件维护，便于新闻、招聘、产品和公共配置统一管理。
4. 支持桌面端和移动端响应式布局。
5. 支持自动生成或维护 `sitemap.xml` 与 `robots.txt`。
6. 支持静态资源优化、图片压缩、代码分割和构建产物检查。

### 3.2 推荐落地方案

若新开工程仓或迁移现有静态实现，推荐优先评估：

| 方案 | 适用性 |
|---|---|
| Astro + TypeScript + 内容集合 | 官网展示型、多语言、SEO、结构化内容维护成本低 |
| Next.js + TypeScript + 静态生成 | 团队偏 React 生态、后续可能扩展动态内容时适用 |
| Nuxt + TypeScript + 静态生成 | 团队偏 Vue 生态、希望延续组件化与内容模块时适用 |

首期不应为了未来 CMS 可能性提前引入复杂后台。内容可先采用 `content/` 或 `data/` 下的结构化 Markdown、MDX、JSON、YAML 文件。

### 3.3 内容模型基线

| 内容对象 | 必填字段 |
|---|---|
| `site_config` | `domain`、`brand_name`、`relation_statement`、`support_channels`、`email`、`icp_text`、`copyright_text` |
| `navigation` | `key`、`label`、`path`、`order`、`locale` |
| `page_seo` | `page_key`、`title`、`description`、`keywords`、`locale` |
| `home_sections` | `section_key`、`headline`、`subheadline`、`body`、`media`、`cta`、`locale` |
| `products` | `slug`、`name`、`summary`、`features`、`scenarios`、`assets`、`cta`、`locale` |
| `news_articles` | `slug`、`category`、`title`、`summary`、`publish_date`、`cover`、`body`、`locale` |
| `job_postings` | `job_id`、`title`、`location`、`job_type`、`summary`、`responsibilities`、`requirements`、`apply_method`、`locale` |
| `about_sections` | `section_key`、`title`、`content`、`media`、`locale` |

4. 招聘页不能只放邮箱，必须具备岗位列表和岗位详情结构。
